# Develop module: Detail (sharpening/noise), Optics (lens corrections), geometry (Transform/Upright/crop), Effects (post-crop vignette/grain), Calibration, Process Versions, and Enhance (AI Denoise, Raw Details, Super Resolution)

This domain covers everything Lightroom does to recover per-pixel fidelity and geometric truth from a raw capture, plus a handful of stylistic finishing effects. The Detail panel implements "capture sharpening" as a four-parameter system (Amount for strength, Radius for edge halo width, Detail for how much fine texture vs. only large edges gets enhanced, and Masking to restrict sharpening to detected edges), with an Alt/Option-key grayscale visualization for each slider and a mandatory 100%-zoom preview philosophy. Noise reduction is split into luminance (Luminance/Detail/Contrast) and chroma (Color/Detail/Smoothness) channels. Since 2023 Adobe has layered a neural-network path on top: AI Denoise (originally a DNG-producing Enhance operation, now integrated as a slider-driven, non-destructive edit as of the June 2025 releases alongside Raw Details and Super Resolution in the edit panel), Raw Details (AI-assisted demosaicing of Bayer/X-Trans mosaics for crisper edges and fewer artifacts), and Super Resolution (2x linear / 4x pixel-count upscaling, capped around 128 MP inputs, GPU-accelerated).

The Optics side is a two-tier system. Profile-based corrections auto-match lens make/model from EXIF against a large database of lens profiles (Adobe's .lcp format) and correct geometric distortion and vignetting, with 0-200% override sliders for each; many mirrorless raws additionally carry embedded, always-on manufacturer opcodes. A one-click "Remove Chromatic Aberration" handles lateral CA analytically, while the Manual tab adds Defringe (purple/green amount + hue-range sliders with an eyedropper) for axial fringing, plus manual distortion and vignette (amount/midpoint) sliders. Geometry is completed by the Transform panel — Upright's automatic modes (Auto, Level, Vertical, Full) that detect lines and solve a perspective correction, Guided Upright where the user draws 2-4 guides that should become vertical/horizontal, and manual Vertical/Horizontal/Rotate/Aspect/Scale/X-Y offset sliders with a Constrain Crop option — and by the Crop tool with preset/custom aspect ratios, an angle slider, a draw-a-line level tool, auto-straighten, cycling composition overlays, and lossless 90-degree rotate and flip.

Finishing effects include post-crop vignetting (three blend styles — Highlight Priority, Color Priority, Paint Overlay — with Amount, Midpoint, Roundness, Feather, Highlights controls, re-centered live as the crop changes) and simulated film grain (Amount/Size/Roughness). The Calibration panel exposes low-level color-science controls: a Shadows tint slider and Hue/Saturation sliders for the red, green, and blue camera primaries, which act on the demosaiced camera data before creative color and are prized for global color-cast fixes and stylized looks. Finally, Process Versions (PV1/2003, PV2/2010, PV3/2012, PV4 2017, PV5 2018, plus later revisions) are Lightroom's mechanism for evolving the rendering pipeline without silently changing old edits — every image records which pipeline version rendered it, and users opt in to migration. For a clone this versioned-pipeline concept is an architectural must-have from day one, even though a v1 only ships one version.

## Feature inventory

| Feature | Priority | Complexity | Description | Building blocks |
|---|---|---|---|---|
| **Capture sharpening (Amount/Radius)** | must | medium | Baseline output-referred sharpening applied to every raw, with Amount (strength, roughly 0-150) and Radius (halo/edge width, ~0.5-3.0 px) controls; conceptually an unsharp-mask/deconvolution hybrid tuned for demosaiced raw softness. | OpenCV (GaussianBlur/filter2D for USM), RawTherapee RL-deconvolution code (GPL reference), darktable sharpen/diffuse modules (reference), Halide or SIMD (highway) for performance |
| **Sharpening Detail slider** | should | medium | Blends between halo-suppressed large-edge sharpening (low values) and high-frequency texture/deconvolution emphasis (high values), controlling how much fine detail is amplified. | Wavelet/pyramid decomposition (OpenCV pyrUp/pyrDown), RawTherapee 'Sharpening > Contrast threshold' approach as reference |
| **Sharpening edge Masking slider** | should | medium | Restricts sharpening to detected edges so smooth areas (skin, sky) stay untouched; 0 sharpens everything, higher values progressively confine the effect to strong edges. | OpenCV Sobel/Canny edge magnitude maps, darktable blend-mask code as reference |
| **Alt-key grayscale slider previews** | could | low | Holding a modifier while dragging Amount/Radius/Detail/Masking shows a diagnostic grayscale rendering (e.g., the edge mask, or luminance-only effect) so users can judge the setting precisely. | Straightforward UI: render intermediate buffers already computed by the sharpen stage |
| **Luminance noise reduction** | must | high | Edge-preserving smoothing of luminance noise with a main strength slider plus Detail (noise-vs-texture threshold) and Contrast (preserves local contrast at cost of blotchiness) refinements. | OpenCV fastNlMeansDenoising, BM3D implementations (bm3d-gpu, pybm3d), darktable 'denoise (profiled)' with camera noise profiles (GPL reference), wavelet shrinkage (RawTherapee) |
| **Color (chroma) noise reduction** | must | medium | Suppresses colored speckle noise separately from luminance, with Detail and Smoothness sliders to control color-edge bleeding and low-frequency color mottling; applied by default to raws. | Chroma-channel median/bilateral filtering in Lab/YCbCr, OpenCV fastNlMeansDenoisingColored, darktable chroma NR paths as reference |
| **AI Denoise** | could | very-high | Neural-network raw denoiser with a single strength slider that removes high-ISO noise while retaining fine detail; historically wrote an enhanced DNG, now applied non-destructively inside the edit pipeline (June 2025 releases), Bayer/X-Trans raw only. | ONNX Runtime / Core ML / TensorRT for inference, pretrained models: NAFNet, Restormer, MIRNet-v2, FFDNet, PMRID, training data: SIDD, DND datasets, LibRaw for raw access |
| **ISO-adaptive default sharpening/NR** | could | low | Per-camera or ISO-dependent defaults so high-ISO files automatically open with stronger noise reduction, and raw vs JPEG files get different baseline sharpening. | Exiv2/ExifTool for ISO metadata, darktable's per-camera noise profile JSON as a data model |
| **Profile-based lens corrections** | must | medium | Auto-identifies the lens from EXIF and applies a database-driven correction of geometric distortion and vignette falloff, with Make/Model/Profile dropdown overrides when auto-match fails. | lensfun database + liblensfun/lensfunpy, Adobe LCP parsing (XML; open format, parsers exist in RawTherapee/darktable), Exiv2 for lens ID |
| **Profile correction amount overrides** | should | low | Separate 0-200% scaling sliders for the profile's distortion and vignetting components, letting users keep some natural vignette or over/under-correct geometry. | Scale the lensfun/LCP correction coefficients before applying |
| **Embedded/built-in lens profile handling** | should | high | Respect correction opcodes embedded in modern mirrorless raw files (often mandatory by design), showing 'built-in profile applied' rather than offering a toggle. | DNG SDK opcode lists (WarpRectilinear, FixVignetteRadial, GainMap), LibRaw/rawspeed metadata extraction, darktable/RawTherapee embedded-correction code as reference |
| **One-click chromatic aberration removal** | must | medium | A checkbox that analytically detects and removes lateral CA (red/cyan, blue/yellow edge fringing) by differentially rescaling color channels, independent of any lens profile. | RawTherapee auto-CA correction algorithm (GPL reference), darktable 'chromatic aberrations' module, per-channel radial rescale via OpenCV remap |
| **Manual Defringe (purple/green)** | should | medium | Targets axial/longitudinal fringing that profile CA cannot fix: Purple Amount + Purple Hue range and Green Amount + Green Hue range sliders, plus an eyedropper that samples a fringe and auto-sets the ranges. | Hue-range desaturation near high-contrast edges; darktable 'defringe' iop as reference |
| **Manual distortion slider** | should | low | Single slider correcting barrel (drag one way) or pincushion (other way) distortion for lenses without profiles, using a simple radial polynomial warp. | OpenCV initUndistortRectifyMap/remap, Brown-Conrady radial model |
| **Manual lens vignetting correction** | should | low | Amount (lighten/darken corners) and Midpoint (how far from corners the falloff reaches) sliders to counteract optical corner darkening pre-crop. | Radial gain map; trivial shader/CPU implementation |
| **Upright automatic perspective correction** | should | high | One-click geometry fixes with four modes: Level (horizon only), Vertical (level + converging verticals), Auto (balanced blend that keeps the image natural), and Full (aggressive combined correction); analyzes detected line segments to solve the warp, and works best with lens profile enabled first. | LSD line-segment detector (OpenCV lsd / pylsd), darktable 'rotate and perspective' (ashift) module — same concept, GPL reference, ceres-solver for the homography optimization |
| **Guided Upright** | could | medium | User draws 2-4 guide lines along features that should be perfectly vertical or horizontal; the app solves and applies the perspective transform interactively as guides are added or adjusted. | Homography from line constraints (OpenCV getPerspectiveTransform / DLT), custom canvas UI for guide handles |
| **Manual Transform sliders** | should | medium | Free geometric controls: Vertical and Horizontal perspective (keystone), Rotate, Aspect (stretch), Scale, and X/Y Offset to reposition the image after warping. | Single composited homography applied with high-quality resampling (Lanczos); OpenCV warpPerspective as prototype |
| **Constrain Crop after warp** | should | low | Option that automatically shrinks/repositions the crop so no transparent/blank areas produced by lens or perspective warps remain in the frame. | Largest-inscribed-rectangle computation on the warped quad (closed-form for homographies) |
| **Crop tool with aspect-ratio presets** | must | medium | Non-destructive crop with locked/unlocked aspect, common presets (1x1, 4x5, 16x9, original), custom user-entered ratios (with a small MRU list), and drag handles plus in-crop image panning. | Custom canvas UI; crop stored as normalized rect + angle in the edit stack (XMP-compatible fields) |
| **Straighten: angle slider, level tool, auto** | must | low | Rotation by a fine-grained angle slider, a ruler tool where the user drags along a horizon/edge that should be level, and an Auto button that detects and levels the horizon automatically. | Hough/LSD line detection for auto-level, angle from user-drawn segment is trivial trig |
| **Crop composition overlays** | could | low | Cyclable guide overlays inside the crop box — grid, rule of thirds, golden ratio, golden spiral, diagonals, and target aspect-ratio frames — to aid composition. | Pure vector overlay drawing in the UI layer |
| **Rotate 90° and flip** | must | low | Lossless quarter-turn rotation (left/right) and horizontal/vertical mirroring, recorded as orientation metadata in the edit state rather than resampling pixels. | EXIF orientation semantics; Exiv2 for reading initial orientation |
| **Post-crop vignette** | should | medium | Stylistic vignette applied relative to the crop (re-centers live when the crop changes) with Amount, Midpoint, Roundness, Feather, and Highlights sliders and three blend styles: Highlight Priority (allows highlight recovery, may shift color), Color Priority (preserves hue, no highlight recovery), and Paint Overlay (flat black/white blend). | Superellipse falloff mask; blend in linear vs. output space to reproduce the three styles |
| **Film grain simulation** | should | medium | Adds photographic-looking grain with Amount, Size, and Roughness controls, useful both stylistically and for masking upscaling/retouch artifacts; grain scales sensibly with output size. | Blue-noise / band-limited procedural noise, G'MIC grain filters, darktable 'grain' module (Perlin-based, GPL reference) |
| **Calibration panel (camera primaries)** | should | medium | Low-level color-science controls applied to camera-native color before creative edits: a Shadows tint slider plus Hue and Saturation sliders for the Red, Green, and Blue camera primaries; small moves cause global, film-like color shifts. | 3x3 primary-matrix manipulation in the camera-to-working-space transform, dcamprof / DNG SDK for camera color math |
| **Process versions (versioned pipeline)** | must | high | Every image records the rendering-pipeline version that produced its edit (Adobe: PV1/2003 through PV5+ with later revisions); opening old edits never silently changes their look, and users explicitly migrate to newer versions. Essential architecture even if v1 ships a single version. | Version field in the edit-state schema (mirrors XMP crs:ProcessVersion), pipeline registry pattern; darktable's module-version/legacy-params system as precedent |
| **Enhance: Raw Details** | wont | very-high | AI-assisted demosaicing pass for Bayer/X-Trans mosaic files that yields crisper edges, better fine-color rendering, and fewer zipper/maze artifacts than conventional demosaicing; targeted at large prints and heavy crops. | Classical near-equivalents: RCD/AMaZE demosaic (RawTherapee/darktable), deep demosaic research code (e.g., joint demosaic+denoise networks), ONNX Runtime for deployment |
| **Enhance: Super Resolution** | could | high | ML upscaler producing 2x linear (4x pixel-count) enlargements with hallucinated-but-plausible detail, with input limits (~128 MP / 32,500 px max dimension); output historically saved as an enhanced DNG. | Real-ESRGAN, SwinIR, HAT, EDSR pretrained models, ncnn / ONNX Runtime for cross-platform GPU inference |
| **Enhance workflow (preview dialog, batch, DNG output)** | could | medium | A unified flow for the heavy AI operations: crop-region preview with estimated processing time, batch application to selections, stacked output next to the original, and (legacy mode) writing results as linear DNG files. | DNG SDK for writing linear DNGs, job queue + GPU scheduling layer |
| **Lens profile import/creation (LCP)** | could | medium | Ability to import third-party or user-created lens correction profiles (Adobe's XML-based .lcp files or lensfun XML) so unsupported lenses can be corrected. | LCP XML parser (reference implementations in RawTherapee/darktable), lensfun XML schema and community DB submission tooling |
| **GPU acceleration of Detail/Optics pipeline** | could | high | Run sharpening, denoising, warping, and the neural Enhance features on the GPU with CPU fallback, since interactive slider feedback on 50+ MP raws is impractical on CPU alone. | wgpu / Vulkan compute / Metal, OpenCL kernels (darktable precedent), Halide cross-compilation, ONNX Runtime execution providers for the ML paths |
