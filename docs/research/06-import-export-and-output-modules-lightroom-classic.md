# Import/Export and output modules (Lightroom Classic + cloud Lightroom)

Lightroom's import pipeline is the front door of the whole application: a dedicated import window shows thumbnails from any source (memory card, device, folder, another catalog) and lets the user choose whether files are copied, moved, referenced in place, or transcoded to DNG on the way in. During that same step the user can batch-rename with token-based templates, stamp develop/metadata presets and keywords, route files into a date-organized destination tree, write a simultaneous backup copy to a second drive, and pre-build previews (including proxy "Smart Previews"). Beyond the dialog, ingestion also happens hands-free through a watched auto-import folder and through tethered capture, where supported Canon/Nikon/Sony/Fujifilm bodies shoot straight into the catalog with live view, remote triggering, and per-session naming.

On the output side, the export dialog is a stack of panels — location, file naming, video, file settings (JPEG/JPEG XL/AVIF/TIFF/PSD/PNG/DNG/original with quality, color space, and bit depth), image sizing (long edge, dimensions, megapixels, percentage, resolution), media-aware output sharpening, metadata filtering/anonymization, watermarking, and post-processing hand-offs — all savable as presets that can be run several-at-a-time in one batch. A parallel "Publish Services" system turns exporting into a stateful sync: collections track which photos are new, modified, or already published to a hard-drive folder or (via plugins) services like Flickr and SmugMug. The Lua-based SDK lets third parties add export destinations, filters, and post-process actions, which historically compensated for Adobe removing built-in Facebook/social connections.

Lightroom Classic additionally ships five whole output modules: Print (contact sheets, picture packages, free-form custom packages, ICC-managed printing with soft proofing and print-to-JPEG), Book (Blurb-integrated photo book designer with auto-layout and PDF/JPEG export), Slideshow (music-synced pan-and-zoom shows exportable to MP4 or PDF), Web (static HTML gallery generation with built-in FTP upload), and Map (Google-Maps-based geotagging with GPX tracklog matching and reverse geocoding into IPTC location fields). Round-trip editing hands photos to Photoshop or any external editor as TIFF/PSD — including open-as-smart-object, open-as-layers, and Photomerge panorama/HDR flows — and returns the result stacked next to the original in the catalog. For a v1 open-source clone, the import dialog, the full export dialog with presets, watermarking, and external-editor round-trip are the load-bearing pieces; the Book/Slideshow/Web modules are legacy surfaces that most users would not miss initially.

## Feature inventory

| Feature | Priority | Complexity | Description | Building blocks |
|---|---|---|---|---|
| **Import dialog with Copy/Move/Add/Copy-as-DNG modes** | must | high | A dedicated import window that ingests files from cards, devices, or folders and lets the user pick whether originals are copied to a managed location, moved, referenced in place (add), or converted to DNG during ingest. Includes a thumbnail grid with per-photo check/uncheck and a 'skip suspected duplicates' toggle based on filename, capture time, and file size. | LibRaw (raw decoding + embedded preview extraction), Exiv2 / ExifTool (metadata read), SQLite (dedupe/tracking state), Qt/GTK file-source browsing |
| **Broad ingest format support (raw, JPEG, HEIC, TIFF, PNG, PSD, video)** | must | high | Import recognizes hundreds of proprietary raw formats plus common bitmap formats and video clips, extracting capture metadata and preview images for each. Video files are cataloged alongside stills even though they are not developed the same way. | LibRaw, libheif, libtiff, libpng, libjpeg-turbo, FFmpeg (video probe + thumbnails), Exiv2 |
| **Token-based file renaming templates** | must | medium | A filename template editor that composes names from tokens such as capture date parts, sequence/import numbers, original name, custom text, and metadata fields; the same template system is reused for import, in-catalog rename, and export. Templates are savable as named presets. | Custom token parser (simple grammar), Exiv2 for metadata token values |
| **Apply-during-import presets and metadata** | must | low | While importing, the user can stamp every incoming photo with a develop preset, a reusable metadata preset (copyright, creator contact info, etc.), and a comma-separated keyword list. Metadata presets are creatable inline from the import window. | XMP templates (Exempi / python-xmp-toolkit), Existing preset engine of the clone |
| **Destination panel with date-based folder organization** | must | medium | A destination tree preview shows exactly which folders will be created before import runs, with options to organize into dated subfolders (many date-format schemes), into one flat folder, or preserving the source hierarchy. New subfolders can be created from within the dialog. | Standard filesystem APIs, ICU/strftime date formatting |
| **Second-copy backup during import** | should | low | An option to simultaneously write an untouched duplicate of every imported file to a second location (typically another drive) as an instant ingest backup. | Filesystem copy with checksum verification (xxHash/SHA-1) |
| **Preview building options at import (minimal/embedded/standard/1:1)** | should | medium | The user chooses how much preview rendering happens at import time, trading import speed against later browsing speed, from reusing camera-embedded JPEGs up to full-resolution rendered previews. | LibRaw embedded thumbnail extraction, Background job queue, Preview cache (tiled pyramid, e.g. custom or libvips) |
| **Smart Previews (lossy proxy raws) generation at import or on demand** | could | high | Compact lossy-compressed proxy files (Adobe uses ~2560px lossy DNGs) that allow full develop editing while the original files are offline or disconnected. Generation can happen during import or later for selected photos. | Adobe DNG SDK (lossy DNG), Alternative: sidecar JPEG-XL/AVIF proxies with a custom offline-editing pipeline |
| **Import presets and card-insert auto-launch** | should | low | The entire import dialog configuration can be saved as a named preset for one-click reuse, and the app can auto-open the import window when a memory card or camera is detected, with optional eject-after-import. | udev/IOKit/WMI removable-media detection, JSON preset serialization |
| **Auto-import watched folder** | should | low | A background watcher monitors a designated folder and automatically moves any file dropped there into a managed location and into the catalog, applying a chosen rename template, develop preset, and metadata without showing the import dialog. Commonly used to bridge third-party tethering tools. | inotify/FSEvents/ReadDirectoryChangesW, watchdog (Python) or efsw (C++) |
| **Tethered capture** | could | very-high | Supported Canon, Nikon, Sony, and Fujifilm cameras connect over USB so shots land directly in the catalog as they are taken, with an on-screen control bar showing exposure settings, a software shutter button, live view for some models, auto-advance to the newest frame, layout overlays for composition, and per-session naming with shot segments. | libgphoto2 (broad PTP/MTP camera control), Canon EDSDK / Sony Camera Remote SDK / Fujifilm SDK (vendor, non-open), Entangle (reference open-source tethering app) |
| **Import from another catalog or other apps' libraries** | could | medium | Merge photos, edits, and collections from a second catalog file, or migrate libraries from tools like Photoshop Elements and Apple Photos/iPhoto, with conflict handling for photos that already exist. | SQLite (Lightroom catalogs are SQLite, aiding a migration importer), XMP sidecar parsing |
| **Export dialog with destination and collision handling** | must | medium | A panelized export window that renders selected photos to a chosen folder (or the source folder), optionally into a subfolder, optionally re-adding results to the catalog, with configurable behavior when a target filename already exists (ask, overwrite, rename uniquely, skip). | Job queue with progress + cancel, The clone's render pipeline |
| **Export file settings: formats, quality, color space, bit depth** | must | high | Output to JPEG (with quality slider and target-file-size limit), PNG, TIFF (8/16-bit, compression choice), PSD, DNG, AVIF, JPEG XL, or a passthrough of the original; color space selection covers sRGB, Adobe RGB, ProPhoto, Display P3, and arbitrary ICC profiles. | libjpeg-turbo / mozjpeg, libpng, libtiff, libavif, libjxl, LittleCMS 2 (ICC conversion), Adobe DNG SDK |
| **Export image sizing and resolution** | must | medium | Resize-to-fit rules by width/height, dimensions, long edge, short edge, megapixel count, or percentage, with a 'don't enlarge' guard and a PPI resolution stamp in inches or centimeters. | libvips or OpenCV (high-quality Lanczos resampling) |
| **Output sharpening for screen/matte/glossy** | should | medium | A one-choice adaptive sharpening pass applied after resize, tuned per output medium (screen, matte paper, glossy paper) and strength (low/standard/high), derived from print-sharpening research rather than exposing raw unsharp-mask controls. | Unsharp mask / deconvolution kernels in libvips or OpenCV, parameterized by output PPI (PhotoKit-Sharpener-style heuristics) |
| **Watermark editor (text and graphic) with presets** | must | medium | A watermark designer supporting styled text (font, color, shadow) or a PNG graphic, with proportional sizing, opacity, edge insets, and a nine-position anchor with rotation; saved watermark presets are selectable in export, publish, print, and slideshow outputs. | Skia or Cairo/Pango (text rendering + compositing), libvips overlay |
| **Export metadata filtering and privacy controls** | must | low | Per-export choice of embedded metadata: copyright only, copyright and contact only, everything except camera/raw develop info, or everything; separate switches remove GPS location and person/face keywords, and keyword hierarchy can be flattened or preserved. | Exiv2 / ExifTool (selective tag writing and stripping) |
| **Export presets, 'Export with Previous', and multi-preset batch export** | must | low | Any export configuration saves as a named preset available from the context menu; a one-keystroke repeat re-runs the last export, and multiple presets can be checked at once so one pass produces several output variants (e.g., full-res TIFF plus web JPEG). | JSON/XML preset store, Parallel render job scheduler |
| **Post-processing actions after export** | should | low | After rendering, exported files can be revealed in the file manager, opened in a chosen application, or handed to a droplet/script placed in an export-actions folder, enabling ad-hoc pipeline chaining. | Process spawning (xdg-open/open/ShellExecute) |
| **Video export and passthrough** | should | medium | Cataloged video clips export either as untouched originals or transcoded H.264 at selectable quality tiers; slideshow video export shares the same encoder. | FFmpeg / libx264 |
| **Publish services framework (stateful sync export)** | should | high | Publish collections remember what has been exported where and sort members into 'new to publish', 'modified to republish', and 'published' buckets; editing an already-published photo automatically queues it for republish, and deletions can propagate to the target. | SQLite state tables (photo-hash + edit-version tracking), The clone's export engine |
| **Hard drive publish connection** | should | medium | A built-in publish target that mirrors a collection to a local/NAS folder using any export settings, effectively an incremental folder-sync exporter useful for screensavers, portfolio folders, or device sync directories. | Filesystem sync logic on top of the publish framework |
| **Online publish connections (Flickr, SmugMug, Adobe Stock) with feedback sync** | could | high | Service connections authenticate with a photo-sharing account, map publish collections to remote albums/photosets, and pull back comments and favorites into the catalog; most services beyond Flickr arrive as third-party plugins. | OAuth libraries, Flickr/SmugMug REST APIs, Existing publish framework as the extension point |
| **Export/publish plugin SDK** | should | very-high | A scriptable plugin architecture (Lua in Lightroom) where third parties define new export destinations, insert render-chain filters, add post-process actions, contribute custom panels to the export dialog, and register publish services; plugins are managed through an in-app plugin manager. This ecosystem (e.g., Jeffrey Friedl's exporters) is a major stickiness factor. | Lua 5.x + sol2, or Python embedding, A stable plugin API surface + sandboxing, darktable's lua API as prior art |
| **Email photos from the app** | could | medium | A share action that renders selected photos at a chosen size preset and attaches them to a message via the system mail client or a configured SMTP account with a built-in address book. | mailto: handoff, libcurl SMTP or language-native SMTP libraries |
| **Print module: contact sheets and single-image layouts** | could | high | A template-driven print layout engine with a live preview: grid-based contact sheets and single-image pages with rulers, margins, cell spacing, stroke borders, identity-plate/text overlays, page numbers, and a template browser with hover previews of saved layouts. | Qt printing / cairo-pdf (page composition), CUPS, Saved-template JSON |
| **Print module: picture package and free-form custom package** | wont | high | Picture package repeats one photo at multiple standard sizes auto-packed onto a sheet, while custom package is a drag-anywhere free canvas mixing many photos at arbitrary sizes with optional photo-border and rotate-to-fit behavior. | 2D bin-packing algorithm, Same page-composition layer as contact sheets |
| **Print color management, soft proofing, and print-to-file** | should | high | Printing supports printer-managed or app-managed color with a chosen ICC profile, perceptual/relative rendering intents, 16-bit output, a brightness/contrast 'print adjustment' nudge, and print sharpening; soft proofing simulates a printer/paper gamut on screen with out-of-gamut warnings, and any layout can render to a JPEG file instead of a printer. | LittleCMS 2 (proof transforms, gamut check), ArgyllCMS profiles, ICC profiles from paper vendors |
| **Book module (photo book designer with Blurb upload)** | wont | very-high | A page-spread editor that auto-fills a book from a collection, offers per-page cell templates, zoom-to-fill controls, caption text cells fed from metadata, page numbering, and background graphics, then either uploads directly to Blurb's print service (with price preview and 20–240 page constraints) or exports a print-ready PDF/JPEG set. | cairo-pdf / PDFium / HexaPDF for PDF generation, Blurb's public API (limited) |
| **Slideshow module with music sync and video export** | wont | high | A slideshow builder with layout guides, backdrop/overlay options (identity plate, ratings, captions), MP3/AAC soundtracks with sync-slides-to-music, pan-and-zoom motion, intro/outro slides, and export to MP4 (up to 4K) or a static PDF; impromptu full-screen playback works from any module. | FFmpeg (frame sequence → H.264 with audio mux), Ken Burns interpolation (simple easing math) |
| **Web module (static HTML gallery generator with FTP upload)** | wont | medium | Generates a self-contained HTML photo gallery from templates with configurable site/gallery titles, contact links, color palettes, and image quality, previews it in-app, then exports to disk or uploads straight to a web server over FTP with saved server presets. | Static-site templating (Jinja2/Handlebars), libcurl FTP/SFTP, thumbsup / sigal as prior art |
| **Map module: geotag browsing and drag-to-tag** | could | medium | An interactive map plots every photo with embedded GPS coordinates as clustered pins; dragging photos from the filmstrip onto the map writes coordinates into their metadata, and a location filter bar restricts the grid to the visible map region. | MapLibre GL / Leaflet + OpenStreetMap tiles, Exiv2 GPS tag writing, marker clustering libs |
| **GPX tracklog matching and reverse geocoding** | could | medium | Loading a GPX tracklog auto-assigns coordinates to photos whose capture times fall along the track (with a timezone offset control), and an opt-in address lookup converts coordinates into suggested city/state/country IPTC fields; saved locations can blur exact coordinates on export for privacy. | gpxpy or libgpx (GPX parsing + time interpolation), Nominatim / Photon (open reverse geocoding), offline reverse-geocoder datasets |
| **External editor round-trip (Edit In)** | should | medium | Sends a photo to Photoshop or any configured external editor, rendering a TIFF/PSD copy with develop edits applied (or the original) at a chosen color space/bit depth/resolution, then automatically re-catalogs the saved result stacked with the source; multiple additional editors can be preset with their own file-format recipes. | libtiff (16-bit TIFF handoff), File watcher for the returned file, GIMP/Krita as the open-source editing targets |
| **Advanced Photoshop hand-offs: smart object, open-as-layers, Photomerge** | wont | high | Deeper Photoshop integrations open a raw file as a Camera-Raw-backed smart object, stack several selected photos into one layered document, or drive Photoshop's panorama/HDR Photomerge with the merged result returned to the catalog. In an open-source clone this maps to scripted hand-offs (e.g., GIMP script-fu layering, Hugin for panoramas). | Hugin (panorama), enfuse/HDRMerge (exposure merge), GIMP scripting for layered open |
| **Cloud share links and invited web galleries (cloud Lightroom)** | could | very-high | The cloud-based Lightroom shares albums as hosted web galleries via link or email invitation, with per-link controls for downloads, metadata visibility, and comments/favorites from viewers flowing back to the owner. A self-hosted clone equivalent would be an optional gallery-server companion. | Self-hostable gallery servers (PhotoPrism, Immich) as integration targets or prior art |
