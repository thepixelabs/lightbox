# Develop module — global adjustments (tone, color, curves, profiles, presets, history, proofing, batch)

Lightroom's Develop module applies global adjustments as a parametric, non-destructive recipe: every slider move is stored as a named parameter value (ultimately serialized to XMP), and the rendering engine re-executes a fixed internal pipeline over the scene-referred raw data no matter what order the user touched controls in. The global toolset spans a live histogram with clipping feedback; white balance (Kelvin temperature/tint, presets, neutral eyedropper); the Basic tone panel (exposure, contrast, highlight/shadow recovery, white/black clipping points, plus an ML-driven Auto); "presence" controls (texture, clarity, dehaze, vibrance, saturation); a tone curve offered in both parametric-region and free point form with per-RGB-channel curves; an 8-band HSL/Color Mixer plus the newer eyedropper-driven Point Color; three-way Color Grading wheels (which replaced legacy Split Toning); a black-and-white channel mix; and a profile system (Adobe raw looks, camera-matching, LUT-based creative profiles with an amount slider, and AI adaptive profiles) that anchors the base rendering before any slider is applied.

Wrapped around those imaging controls is workflow scaffolding that all rides on the same parameter-set abstraction: a persistent History log and named Snapshots stored in the catalog, Before/After comparison views, ICC soft proofing with gamut warnings and proof copies, selective Copy/Paste of settings, Sync and live Auto Sync across selections, a full presets system (import/export, hover previews, intensity amount, ISO-adaptive rules, AI adaptive presets), and batch application at import or via Quick Develop's relative adjustments. Process Versions keep old edits rendering identically as the engine evolves.

For a v1 Lightbox clone the architectural insight is that one uniform "edit state = serializable parameter set" design buys presets, copy/paste, sync, snapshots, history, and batch almost for free once the pipeline exists. The genuinely hard imaging work concentrates in a few places: a quality raw base rendering/profile stage (DCP handling), halo-free highlight/shadow recovery, smooth hue-band weighting for the color mixer, and the frequency-aware presence tools (texture/clarity/dehaze). Open-source raw editors (darktable, RawTherapee, ART) provide reference implementations for nearly all of it, and libraries like LibRaw, lcms2, OpenColorIO, and the Adobe DNG/XMP SDKs cover decoding, color management, LUTs, and metadata.

## Feature inventory

| Feature | Priority | Complexity | Description | Building blocks |
|---|---|---|---|---|
| **Live histogram with clipping indicators** | must | medium | Real-time RGB-overlay histogram of the rendered image, with per-corner shadow/highlight clipping triangles, toggleable red/blue clipping overlays on the image, and draggable histogram regions that map directly to the blacks/shadows/exposure/highlights/whites sliders. | Custom GPU reduction (OpenGL/Vulkan compute or Halide), darktable histogram/scopes code as GPL reference |
| **White balance temperature and tint sliders** | must | medium | Correlated color temperature (Kelvin for raw, relative -100..+100 for rendered files) and green-magenta tint controls applied in a scene-referred space via chromatic adaptation. | LibRaw / rawspeed (as-shot WB metadata), colour-science (Python reference for CCT math), Bradford/CAT02 adaptation matrices, RawTherapee WB code as reference |
| **White balance presets** | must | low | One-click WB starting points: As Shot, Auto, Daylight, Cloudy, Shade, Tungsten, Fluorescent, Flash, and Custom, each resolving to a temp/tint pair for the current image. | Standard illuminant CCT tables, gray-world / robust AWB algorithms (libraw, darktable) for Auto |
| **White balance eyedropper** | must | medium | Click a should-be-neutral pixel to solve temp/tint automatically, with a magnified loupe grid showing sampled RGB values before committing. | Neutral-target WB solve (invert adaptation so sampled patch becomes achromatic); darktable spot WB as reference |
| **Exposure slider** | must | low | Overall brightness control calibrated in photographic stops (+1.00 behaves like opening the aperture one stop), implemented as a linear gain on scene-referred data with soft highlight rolloff. | Simple linear multiply in float pipeline; ACES/filmic rolloff curves as reference for shoulder handling |
| **Contrast slider** | must | low | Single slider that steepens or flattens the tone curve around the midtones, increasing or decreasing global contrast without moving the endpoints much. | Sigmoid/S-curve around mid-gray pivot; darktable sigmoid module as reference |
| **Highlight and shadow recovery** | must | high | Independent sliders that compress bright quarter-tones to recover blown detail and lift dark three-quarter-tones to open shadows, using spatially adaptive (local, halo-suppressed) tone mapping rather than a plain curve. | Guided filter (OpenCV ximgproc), local Laplacian pyramids, darktable tone equalizer & RawTherapee dynamic range compression as references, raw highlight reconstruction from unclipped channels (LibRaw/darktable) |
| **Whites and blacks clipping points** | must | medium | Sliders setting the white and black endpoints of the tone curve, with Alt/Option-drag threshold visualization showing exactly which pixels clip, and auto-computed endpoints via Shift-double-click. | Histogram percentile analysis for auto endpoints, threshold visualization shader |
| **Auto tone (ML-assisted)** | should | high | One click sets exposure, contrast, highlights, shadows, whites, blacks, vibrance, and saturation to machine-learned per-image values; users can then refine from that baseline. A v1 can ship a histogram-heuristic version before an ML model. | ONNX Runtime, HDRNet-style or white-box 'Exposure' RL models, MIT-Adobe FiveK dataset for training, percentile-based heuristic auto-levels as fallback |
| **Texture slider** | should | high | Boosts or smooths mid-frequency detail (pores, fabric, foliage) while leaving fine noise and large tonal transitions mostly untouched; negative values act as skin-friendly smoothing. | Wavelet band decomposition (darktable contrast equalizer, RawTherapee wavelet levels as references), frequency separation via Gaussian/guided pyramid |
| **Clarity slider** | should | medium | Midtone local contrast enhancement with a larger radius than texture, adding punch and apparent depth; negative values give a soft, dreamy rendering. | Large-radius unsharp mask on luminance with midtone mask, bilateral/guided filter local contrast (OpenCV, darktable local contrast module) |
| **Dehaze slider** | should | high | Estimates and removes (or adds, at negative values) atmospheric haze, restoring contrast and color saturation in distant or foggy scenes. | Dark channel prior (He et al.) implementations, darktable haze removal module (GPL reference), OpenCV |
| **Vibrance slider** | must | medium | Saturation boost weighted toward already-muted colors, with built-in protection for skin tones so faces do not go orange before the rest of the image saturates. | Chroma-weighted saturation gain with hue-based skin protection; darktable velvia/vibrance as reference |
| **Saturation slider** | must | low | Uniform global chroma scaling applied equally to all colors, from full desaturation (-100) to doubled intensity (+100). | Chroma scale in Oklab/JzAzBz or HSL working space |
| **Parametric tone curve** | should | medium | Region-based curve editing via four sliders (highlights, lights, darks, shadows) plus draggable split-point controls that redefine where each region begins and ends. | Weighted region falloff functions composited into a monotone spline; RawTherapee parametric curve as reference |
| **Point tone curve** | must | medium | Freeform curve with user-placed control points on a luminance axis, canned starting shapes (linear, medium contrast, strong contrast), and point deletion/reset. | Monotone cubic interpolation (PCHIP/Akima) or Catmull-Rom with clamping, 1D LUT baking for GPU |
| **Per-channel RGB curves** | must | low | Separate point curves for the red, green, and blue channels enabling color casts, cross-processing looks, and channel-specific contrast, alongside the composite luminance curve. | Same spline engine as point curve, applied per channel as three 1D LUTs |
| **Targeted Adjustment Tool (TAT)** | could | medium | Pick the tool, then drag up/down directly on an image region to modify the underlying curve, HSL band, or B&W mix values that correspond to the pixels under the cursor. | Pixel sampling to parameter mapping (hue-band or luminance-zone lookup); UI plumbing only, reuses existing adjustments |
| **HSL / Color Mixer** | must | high | Eight named color bands (red, orange, yellow, green, aqua, blue, purple, magenta) each with hue-shift, saturation, and luminance sliders, using smooth overlapping band weights so adjacent colors blend without banding. | Gaussian/raised-cosine hue-band weighting in a perceptual space, darktable color zones module as GPL reference |
| **Point Color** | could | high | Eyedropper-sample any color in the photo, then shift its hue, saturation, and luminance with adjustable range and variance (falloff) controls and a visualization of the affected gamut region; supports multiple sampled swatches. | 3D color-distance weighting around sampled point (Oklab); no direct OSS equivalent — custom kernel, OpenCV for prototyping |
| **Color Grading three-way wheels** | should | high | Separate hue/saturation color wheels for shadows, midtones, and highlights plus a global wheel, each with its own luminance slider, and Blending/Balance sliders controlling how the three tonal zones overlap and where their boundaries sit. | ASC CDL-style lift/gamma/gain math with luminance-zone masks, darktable color balance rgb as reference, custom wheel widget |
| **Legacy split toning compatibility** | wont | low | The older highlights/shadows hue+saturation plus balance model that Color Grading superseded; only needed to correctly interpret old presets and XMP files, mapping them onto the grading wheels. | XMP parameter mapping table (split toning params are a strict subset of color grading) |
| **Black & white conversion with channel mix** | should | medium | A treatment toggle that switches the image to monochrome and exposes eight per-color luminance sliders controlling how each original hue translates to gray, plus an Auto mix based on the image's white balance. | Hue-band weighted luminance mixing (shares the HSL band engine), darktable/RawTherapee B&W modules as references |
| **Camera profiles (base raw rendering)** | must | high | Selectable profiles that define the base color/tone rendering of a raw file before sliders apply — a vendor-neutral default family (like Adobe's Color/Standard/Landscape/Portrait/Vivid/Neutral/Monochrome) built from DCP-style camera characterization data. | Adobe DNG SDK (open source, includes DCP reading), dcamprof / Lumariver approach for building profiles, RawTherapee DCP support code, LibRaw color matrices as fallback |
| **Camera-matching profiles** | could | high | Per-manufacturer profiles that emulate the in-camera picture styles (e.g., a body's own Standard/Vivid/Portrait JPEG looks) so the raw rendering matches what photographers saw on the camera LCD. | dcamprof-generated DCPs from target shots, community DCP/ICC profile packs, RawTherapee bundled camera profiles |
| **Creative profiles with amount slider** | should | medium | Stylistic looks implemented as 3D LUT-based profiles (artistic, vintage, modern, B&W families) applied on top of the base rendering, browsable in a grid with hover previews, favorites, and a 0-200% intensity amount slider. | OpenColorIO, .cube LUT parsing, HaldCLUT collections (RawTherapee film simulation packs), LUT interpolation shaders |
| **Adaptive AI profiles** | wont | very-high | Content-aware profiles (adaptive color and adaptive B&W) that analyze each image with ML and produce a per-image optimized base rendering rather than a fixed transform. | ONNX Runtime, image-to-parameter or image-to-LUT regression networks (HDRNet lineage), MIT-Adobe FiveK / PPR10K datasets |
| **Develop presets system** | must | medium | Create, apply, rename, group, import, and export named parameter bundles; creation dialog lets the user check exactly which setting groups a preset stores (partial presets), and hovering a preset live-previews it on the current photo. | XMP serialization (Adobe XMP Toolkit SDK, BSD; or exiv2), compatibility layer for reading existing .xmp Lightroom presets, SQLite for preset catalog |
| **Preset amount slider** | could | medium | After applying a preset, a single intensity control scales the preset's combined effect above or below 100% by interpolating/extrapolating its parameter deltas. | Parameter-space linear interpolation between pre/post states (nonlinear params like curves need per-type blend rules) |
| **ISO-adaptive presets** | could | medium | Presets that store different values (e.g., noise reduction, sharpening, texture) keyed to ISO ranges and interpolate between anchor ISOs, so one preset applies sensible settings across a whole shoot from base ISO to high ISO. | EXIF ISO via exiv2/ExifTool, piecewise-linear interpolation over log-ISO anchors in the preset schema |
| **Adaptive AI presets** | wont | very-high | Presets that embed AI-computed masks (subject, sky, background, facial regions) so the same preset applies its adjustments only to the semantically relevant areas of each individual photo. | Segment Anything / SAM 2, ONNX Runtime, semantic segmentation models (sky/person), mask-referencing preset schema |
| **Snapshots** | should | low | Save the complete current edit state under a user-chosen name at any time; snapshots persist in the catalog and can be recalled, updated, or deleted, enabling multiple named looks per photo. | Serialized parameter-set rows in SQLite (reuses preset serialization) |
| **History panel** | must | medium | A persistent, chronological log of every edit step since import (surviving app restarts, stored in the catalog); clicking any entry previews and restores that state, and history can be cleared or a step promoted to a snapshot. | Append-only edit-state log in SQLite, parameter-delta compression to keep the log small |
| **Before/After comparison views** | must | medium | Toggle an unedited 'before' (backslash key), plus side-by-side, top/bottom, and split-screen layouts; the before state is user-assignable, and settings can be copied in either direction between before and after. | Dual render of two parameter sets from the same decoded raw; viewport split shader |
| **Reference view** | could | low | Pin a second, different photo next to the one being edited so its color and tone can be matched by eye — useful for consistent series or matching a client sample. | Second image viewport; no new imaging code required |
| **Soft proofing** | should | high | Preview the image through a chosen output ICC profile (printer/paper or display standard) with perceptual/relative-colorimetric intents, simulated paper white and ink black, destination and monitor gamut warnings, and one-click creation of a proof virtual copy to edit toward that output. | Little CMS 2 (lcms2) transforms, gamut-check pseudo-color, ICC profile parsing, virtual-copy mechanism from catalog layer |
| **Copy/paste develop settings** | must | medium | Copy the current photo's settings with a checklist dialog choosing exactly which groups (WB, tone, curves, color mixer, grading, profile, etc.) travel, then paste onto one or many other photos. | Parameter-set diff/merge over the same serialization used by presets |
| **Sync and Auto Sync** | must | medium | Apply the most-selected photo's chosen setting groups to an entire selection in one action (Sync), or flip on Auto Sync so every slider move is broadcast live to all selected photos while editing. | Multi-photo parameter broadcast plus background re-render queue |
| **Batch application and Quick Develop** | should | medium | Apply presets automatically at import time, use a 'Previous' command to repeat the last photo's settings, and make relative (incremental) adjustments to many photos at once from a Library-side Quick Develop panel that nudges each photo's existing values rather than overwriting them. | Job queue with worker pool for re-rendering previews, relative vs absolute parameter-op distinction in the edit schema |
| **Process versions** | could | medium | Every edit records which generation of the processing engine created it, and old versions keep rendering bit-faithfully after the pipeline evolves, with an explicit opt-in upgrade path per photo. | Versioned pipeline modules with frozen legacy code paths (darktable's module-version system as a working example) |
