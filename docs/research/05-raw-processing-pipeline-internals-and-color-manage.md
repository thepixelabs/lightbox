# Raw processing pipeline internals and color management

Lightroom (Classic and cloud) is built around the Adobe Camera Raw engine: a fully non-destructive, parametric pipeline that decodes a camera's mosaic sensor data, demosaics it, and processes everything as 32-bit floating-point linear RGB in a fixed, non-user-selectable working space (ProPhoto primaries with a linear tone response; histograms and readouts are shown through a companion space nicknamed "Melissa RGB" that pairs ProPhoto primaries with an sRGB-like curve). Sensor color is mapped to real-world color via DNG Camera Profiles (DCP), which combine dual-illuminant color matrices, forward matrices, 3-D hue/sat/value lookup tables, and profile tone curves; Adobe ships a colorimetric "Adobe Standard/Color" family, camera-matching profiles that emulate manufacturer JPEG looks, and newer XMP-based "enhanced" profiles that can embed 3D LUTs. The rendering engine itself is versioned ("process versions" 1 through 6) so images edited years ago re-render pixel-identically, and every edit is stored as a settings recipe — in the catalog database and optionally in XMP sidecar files next to proprietary raws (or embedded in DNG/JPEG/TIFF) — leaving originals untouched.

The format layer is equally central: Camera Raw decodes 400+ proprietary raw formats (CR2/CR3, NEF, ARW, RAF including X-Trans, ORF, RW2, and so on), and Adobe's DNG format acts as both an archival container (with options like lossy compression, linear DNG, Fast Load Data, embedded original raws, and checksum validation) and the vehicle for newer capabilities: DNG 1.7 adds JPEG XL payload compression, and floating-point DNG carries HDR-merge results through the same develop pipeline. Since 2023 Lightroom offers a true HDR editing mode — extended-range histogram, editing above SDR white on EDR/HDR displays, SDR-rendition controls — and exports HDR as JPEG-with-gain-map (base SDR image plus a ratio map so any viewer degrades gracefully), AVIF, or JPEG XL. Display output is color-managed automatically against each monitor's ICC profile, soft proofing simulates printer/output profiles with gamut warnings, and most of the develop pipeline plus export can run on the GPU (Metal/DirectX). Around the core sit tethered capture (Canon/Nikon/Sony/Fujifilm), basic video cataloging/trimming (full video grading in cloud Lightroom), and ML stages that operate directly on mosaic data: Raw Details (CNN demosaicing), Super Resolution (2x raw upscale), and Denoise — all made non-destructive toggles in the 2025 releases instead of writing separate enhanced DNGs.

The open-source world already covers most of this ground, which matters for a Lightbox clone. Raw decoding: LibRaw, rawspeed (darktable's decoder), rawler (Rust, powers dnglab), libopenraw. Demosaicing and highlight reconstruction: RawTherapee's AMaZE/DCB/LMMSE and darktable's RCD plus Markesteijn for X-Trans. Color: Little CMS 2 for ICC, OpenColorIO for transform pipelines, dcamprof/dcpTool for building and manipulating DCP profiles (RawTherapee already applies DCPs; ART inherits this), lensfun for lens corrections alongside LCP parsing. Formats: Adobe's freely licensed DNG SDK and XMP Toolkit, dnglab for DNG writing, libjxl/libavif/libheif/libultrahdr for modern and gain-map HDR outputs, exiv2/ExifTool for metadata, FFmpeg for video, libgphoto2 for tethering. Architecturally, darktable's "pixelpipe" (an ordered module chain that is scene-referred/linear until a late tone-mapping stage, with OpenCL acceleration and versioned modules) and RawTherapee's fixed-order engine are the closest existing blueprints to Camera Raw's design, and vkdt demonstrates a fully GPU-resident (Vulkan) raw pipeline.

## Feature inventory

| Feature | Priority | Complexity | Description | Building blocks |
|---|---|---|---|---|
| **Proprietary raw format decoding** | must | high | Decode the mosaic sensor data, metadata, and embedded previews of hundreds of camera-specific raw formats (CR2/CR3, NEF/NRW, ARW, RAF, ORF, RW2, PEF, IIQ, 3FR, SRW, DNG, etc.), with ongoing updates as new camera bodies ship. | LibRaw, rawspeed (darktable), rawler (Rust, used by dnglab), libopenraw, ExifTool tag tables as format reference |
| **Raw linearization and sensor normalization** | must | medium | Pre-demosaic stage that applies linearization curves, subtracts per-channel black levels, clips to white level, handles masked/optical-black areas, and maps bad pixels so downstream math sees normalized linear sensor values. | LibRaw, rawspeed, DNG spec LinearizationTable/BlackLevel semantics, darktable 'raw black/white point' module as reference |
| **High-quality Bayer demosaicing** | must | high | Interpolate the Bayer color filter array into full RGB with an algorithm that minimizes false color, zippering, and maze artifacts; this is the quality-defining stage of the whole pipeline. | AMaZE/DCB/LMMSE/IGV implementations in RawTherapee (librtprocess), RCD and PPG in darktable, OpenCV demosaic as a fallback |
| **X-Trans and non-Bayer sensor support** | should | high | Dedicated demosaicing for Fujifilm's 6x6 X-Trans pattern plus handling of monochrome sensors, quad-Bayer style layouts, and pixel-shift composites so those cameras render without artifacts. | Markesteijn 1/3-pass X-Trans demosaic (RawTherapee, darktable), librtprocess |
| **Highlight reconstruction** | should | medium | Rebuild plausible detail and color in areas where one or more raw channels clipped, using the surviving channels and neighborhood propagation instead of leaving magenta or flat-white patches. | darktable 'inpaint opposed' and 'segmentation' highlight modules, RawTherapee color-propagation reconstruction, HDRMerge clipping logic as reference |
| **White balance model (As Shot / presets / Kelvin+tint)** | must | medium | Read the camera's as-shot multipliers from raw metadata and convert between raw channel gains and a correlated-color-temperature + tint model using the camera's color matrices, with daylight/tungsten/etc. presets and an eyedropper-compatible representation. | LibRaw cam_mul metadata, DNG spec CCT math (AsShotNeutral, CalibrationIlluminant), darktable temperature module as reference |
| **DCP camera profile engine** | must | high | Apply DNG Camera Profiles to map sensor color to scene color: dual-illuminant ColorMatrix/ForwardMatrix interpolation by white point, HueSatDelta 3-D lookup tables, LookTable, and ProfileToneCurve, matching how Adobe renders each camera. | Adobe DNG SDK, RawTherapee's dcp.cc implementation, dcamprof (build profiles from targets), dcpTool (decompile/edit DCPs) |
| **Default look and camera-matching profiles** | should | high | Ship a neutral colorimetric base profile per camera plus an opinionated default look (the Adobe Color analogue) and optional profiles that emulate each manufacturer's in-camera JPEG picture styles. | dcamprof with ColorChecker/IT8 target shots, Lumariver-style workflows, community DCP collections, darktable base curves / styles as prior art |
| **Creative profiles with embedded 3D LUTs** | could | medium | A browsable profile system (separate from presets) where look profiles can carry 3D LUTs and expose an intensity slider, applied as a rendering layer rather than as slider edits. | OpenColorIO, .cube LUT parsers, darktable lut3d module |
| **Manual camera calibration controls** | could | low | Sliders that tweak the profile's red/green/blue primaries and shadow tint on top of the selected camera profile, for users who fine-tune or cross-match camera color by hand. | RawTherapee Color Management channel mixer primaries, darktable color calibration module |
| **Full DNG reading** | must | high | Read the complete DNG spec: tiled and strip layouts, lossless JPEG and JPEG XL (DNG 1.7) compression, lossy DNG, linear (pre-demosaiced) DNG, floating-point DNG, transparency/enhanced image tags, and embedded profiles. | Adobe DNG SDK, rawspeed, rawler/dnglab, libjxl, libtiff |
| **DNG writing and conversion** | should | high | Convert proprietary raws to DNG on import or on demand (the DNG Converter role), with choices for compression (including lossy and JPEG XL), linear output, and compatibility level targeting. | dnglab (Rust DNG writer), Adobe DNG SDK, libjxl |
| **DNG convenience features** | could | medium | Support Fast Load Data (cached partially-processed data for quicker develop loading), embedding the original proprietary raw inside the DNG, refreshable embedded previews, and checksum-based file validation to detect corruption. | Adobe DNG SDK (validation, embedded original), dnglab |
| **DNG opcode and embedded correction processing** | must | high | Execute correction recipes embedded in raw/DNG files by the camera maker — geometric warp, vignette gain maps, and bad-pixel fixes — which modern mirrorless lenses depend on for acceptable output. | Adobe DNG SDK opcode lists (WarpRectilinear, GainMap, FixBadPixels), darktable/RawTherapee embedded-correction handling |
| **Lens profile (LCP) correction support** | should | medium | Apply per-lens distortion, chromatic aberration, and vignetting corrections from Adobe's LCP profile format or an equivalent database, selected automatically from EXIF lens identification. | lensfun, RawTherapee's LCP parser, exiv2 for lens ID |
| **32-bit float scene-linear pipeline** | must | high | All internal processing in 32-bit floating point on linear data, with no intermediate clipping, so highlight recovery, HDR merge results, and 16/32-bit TIFF or float-DNG sources keep their full range through every stage. | darktable pixelpipe (4x32-bit float) as blueprint, Halide, OpenEXR/half for interchange |
| **Fixed wide-gamut working space with display transform** | must | medium | A non-configurable working space using ProPhoto-class primaries and linear encoding, paired with a perceptual display transform (ProPhoto primaries + sRGB-like curve, Adobe's 'Melissa RGB' analogue) used for histograms, readouts, and previews. | Little CMS 2, OpenColorIO, elles_icc_profiles (well-behaved ProPhoto/ACES profiles) |
| **Versioned rendering engine (process versions)** | must | medium | Tag every image's edits with the engine version that produced them (Lightroom has PV1 through PV6) and keep old versions renderable forever, so improving algorithms never silently changes existing photos; offer explicit migration. | darktable's per-module version/introspection system as prior art |
| **Non-destructive parametric edit storage** | must | medium | Edits are a recipe of named parameters replayed against the untouched original on every render; nothing is baked until export, and the same recipe drives previews, exports, and copies. | darktable history-stack model, RawTherapee .pp3 sidecar model, SQLite for catalog-side storage |
| **XMP sidecars and embedded XMP** | must | medium | Serialize develop settings and metadata as XMP — sidecar .xmp files beside proprietary raws (never rewriting them), embedded XMP blocks inside DNG/TIFF/JPEG — using a documented namespace so edits are portable across tools. | Adobe XMP Toolkit SDK (BSD), exiv2, ExifTool, Adobe's crs namespace as a compatibility reference |
| **Catalog/XMP synchronization and conflict handling** | should | medium | Database remains the source of truth with an opt-in 'auto-write to XMP' mode, manual save/read-metadata commands, and detection badges when file metadata and catalog state diverge. | SQLite, file watchers (fsevents/inotify) |
| **Display color management** | must | medium | Automatically transform rendered previews through each connected monitor's ICC profile (per-window on multi-display setups), so what the user sees is correct on wide-gamut and standard screens without configuration. | Little CMS 2 (fast-float plugin), colord / Wayland color-management protocol, Windows ICM / macOS ColorSync APIs, ArgyllCMS for profiling |
| **Soft proofing** | should | medium | Preview an image through a chosen output ICC profile (printer/paper or sRGB) with perceptual or relative-colorimetric intents, paper-white simulation, and both destination-gamut and monitor-gamut warning overlays, with proof-specific virtual copies. | Little CMS 2 (proofing transforms, gamut check), darktable/RawTherapee soft-proof implementations |
| **Export color management** | must | low | Render exports to sRGB, Adobe RGB, ProPhoto, Display P3, Rec.2020, or any user ICC profile, at 8/16-bit integer or float depths, with the profile embedded in the output file. | Little CMS 2, libtiff/libjpeg-turbo/libpng metadata embedding |
| **HDR editing mode** | could | very-high | An opt-in extended-dynamic-range edit mode: histogram and controls extend above SDR white (measured in stops), previews use the display's EDR/HDR headroom on capable hardware, and separate SDR-rendition controls define how the image degrades on SDR screens. | macOS EDR (Metal extended range), Windows HDR via DXGI/DirectX, PQ/HLG transfer function implementations in OpenColorIO |
| **HDR export with gain maps** | could | high | Export HDR photos as JPEG with an ISO 21496-1 style gain map (SDR base plus ratio map so unaware viewers see a good SDR image), and as native HDR AVIF or JPEG XL; also read gain-map images from phones. | libultrahdr (Google), libavif, libjxl, libheif |
| **HDR merge to floating-point DNG** | should | high | Merge bracketed exposures (with deghosting) into a single floating-point linear DNG that flows through the normal develop pipeline with extended slider ranges, rather than producing a tone-mapped bake. | HDRMerge (open-source, writes float raw DNG), OpenCV (alignment/deghosting), dnglab for float-DNG output |
| **ML raw enhancement (Raw Details / Super Resolution / Denoise)** | could | very-high | Neural stages that run on mosaic data: CNN-based demosaicing for finer detail (notably on X-Trans), 2x linear-resolution raw upscaling, and raw-domain denoising — integrated as non-destructive toggles in the develop pipeline (as of Lightroom's 2025 releases) instead of emitting separate enhanced DNGs. | ONNX Runtime / CoreML / DirectML for inference, demosaicnet-style research models, Real-ESRGAN/SwinIR for SR, NAFNet/Restormer for denoise, darktable profiled-denoise as classical fallback |
| **GPU-accelerated processing** | should | very-high | Run the develop preview, full-resolution image processing, preview generation, and export on the GPU with automatic capability detection (auto/limited/full tiers) and a bit-exact CPU fallback path. | darktable's OpenCL pipeline, vkdt (Vulkan compute raw pipeline), wgpu, Halide (CPU/GPU scheduling from one kernel source) |
| **Tethered capture** | could | high | Shoot over USB from Canon, Nikon, Sony, and Fujifilm bodies with images landing directly in the catalog, plus remote shutter, exposure-setting control, and live view for supported models; auto-apply develop settings to incoming frames. | libgphoto2, manufacturer SDKs (Canon EDSDK, Sony Camera Remote SDK) where licensing allows, digiCamControl/Entangle as references |
| **Video file handling** | could | high | Import and catalog MP4/MOV/AVI/AVCHD/HEVC clips with thumbnails and playback, trim in/out points, set poster frames, capture stills, and apply a limited subset of develop settings via presets (Lightroom Classic) — full slider-based video grading exists only in cloud Lightroom. | FFmpeg/libav, libmpv or GStreamer for playback, hardware decode APIs (VideoToolbox, D3D11VA, VA-API) |
| **Non-raw image format support** | must | medium | Import and non-destructively edit JPEG, TIFF (8/16/32-bit), PNG, PSD, HEIC/HEIF, and AVIF through the same parametric pipeline, treating the decoded image as display-referred input converted into the working space. | libjpeg-turbo, libtiff, libpng, libheif, libavif, OpenImageIO, psd_sdk / libpsd for PSD reading |
