# Library module / digital asset management (Adobe Lightroom Classic + cloud Lightroom)

Lightroom's Library module is the DAM heart of the product. Everything revolves around a catalog: a single-file database (Adobe uses SQLite) that records where each original file lives on disk plus every piece of user-applied data — ratings, flags, labels, keywords, collection membership, edit history and virtual copies — without ever modifying the originals. Photos enter the catalog through a rich import pipeline (copy, move, add-in-place, or convert-to-DNG; file renaming templates; second backup copy; metadata/keyword/develop presets applied on ingest; preview pre-rendering; optional skip-suspected-duplicates), and can also arrive via watched-folder auto-import or tethered capture. The physical organization (Folders panel mirroring the filesystem) is deliberately separated from logical organization (collections, collection sets, and rule-driven smart collections), and a robust missing-file/relink workflow keeps the database and disk reconciled when files move outside the app.

Triage and retrieval are the module's second pillar. Users cull through four classic view modes — Grid, Loupe, Compare (candidate vs. select with synchronized zoom), and Survey — recently joined by a People view and a Duplicates view, assigning star ratings, pick/reject flags, and color labels via one-key shortcuts. Retrieval combines a filter bar (free-text search across metadata, attribute filters, and a drill-down metadata column browser) with hierarchical keywords (synonyms, export control, suggestion lists, a spray-paint tool for bulk application) and full EXIF/IPTC viewing and editing, round-tripped to XMP sidecars for interoperability. A multi-tier preview system (embedded, standard, 1:1, and lossy-DNG "smart previews" that permit editing when originals are offline) keeps browsing fast, while stacking, virtual copies, and Quick Develop provide lightweight versioning and batch adjustment without leaving the Library.

Adobe's recent direction adds AI on top of this foundation: on-device face recognition groups photos by person; Assisted Culling scores subject sharpness, eye focus, and eyes-open per face to pre-select keepers; content-similarity duplicate detection auto-stacks redundant frames; and the cloud product goes further with server-side semantic search that finds photos by describing their content with no keywording at all. For an open-source clone, the non-negotiable v1 core is the catalog, import, folders/collections/smart collections, ratings/flags/labels, keywording, metadata + XMP, the filter bar, grid/loupe views, previews, missing-file handling, and virtual copies; face recognition, semantic search, and AI culling are differentiators that can ride on open models (InsightFace, OpenCLIP, MediaPipe) later.

## Feature inventory

| Feature | Priority | Complexity | Description | Building blocks |
|---|---|---|---|---|
| **Catalog database** | must | high | A single-file database that indexes every photo by reference (originals stay untouched on disk) and stores all user data: ratings, keywords, collections, edit parameters, history. All organization work is nondestructive writes to this database. | SQLite (Lightroom's own catalog is SQLite), Diesel/sqlx (Rust) or SQLAlchemy (Python) ORM, digiKam and darktable database schemas as reference implementations |
| **Import pipeline (copy / move / add / convert)** | must | high | Ingest from cards, folders, or devices with four modes: copy to a managed destination, move, add in place, or convert to DNG on ingest. Includes destination folder templates (e.g. date-based), file renaming templates, and an optional simultaneous second backup copy. | LibRaw / rawspeed (raw decoding), Adobe DNG SDK (freely licensed) for DNG conversion, exiv2 or ExifTool for reading capture dates used in folder templates |
| **Apply-on-import presets and metadata** | should | medium | During import, apply a develop preset, a metadata preset (copyright, creator), and starter keywords to every incoming file, and choose which preview sizes to pre-render. | exiv2 (IPTC/XMP writing), JSON/TOML preset serialization |
| **Skip suspected duplicates at import** | must | low | The import grid greys out files already in the catalog (matched on filename, capture time, and size) so re-inserting a half-downloaded card doesn't create duplicates. | SHA/xxHash content hashing, SQLite unique indexes |
| **Watched-folder auto-import** | should | low | Monitors a designated folder and automatically moves and imports anything dropped into it, commonly used to bridge third-party tethering software. | fsnotify / notify-rs / Python watchdog (filesystem events) |
| **Tethered capture** | could | very-high | Direct camera control from the app: fire the shutter, see frames land in the catalog live, with per-session naming and develop settings applied as frames arrive. | libgphoto2 (broad camera protocol support), Canon EDSDK / Sony SDK (proprietary, gated) |
| **Folders panel (physical organization)** | must | medium | A live mirror of the on-disk folder hierarchy: create, rename, move folders and files from inside the app with the catalog kept in sync, plus a 'synchronize folder' scan that reconciles disk changes made outside the app. Folders can be marked favorite or color-coded. | std filesystem APIs + fsnotify, SQLite transactions for atomic move+update |
| **Collections and collection sets** | must | low | Virtual albums independent of disk location; one photo can live in many collections at zero storage cost, and collections nest inside collection sets. Collections support custom drag-to-reorder sort. | Many-to-many join tables with an ordering column in SQLite |
| **Smart collections (saved rule queries)** | must | medium | Self-updating collections defined by stackable rules (rating, label, keyword, camera, lens, date, edit state, etc.) with any/all/none boolean grouping and nested condition groups. | Rule-AST-to-SQL query builder, JSON-serialized rule trees |
| **Quick Collection / target collection** | should | low | A scratch collection with a single-key toggle (B) for gathering candidates while browsing; any collection can be designated the current 'target' of that shortcut. | — |
| **Star ratings** | must | low | 0-5 star ranking applied with number-key shortcuts, optionally auto-advancing to the next photo for fast culling passes. | xmp:Rating field for interop |
| **Pick / reject flags** | must | low | Ternary flag state (picked, unflagged, rejected) with P/U/X shortcuts; rejected photos dim in the grid and a 'delete rejected' command purges them in one step. | — |
| **Color labels with custom label sets** | must | low | Assignable color tags (red through purple, and recently up to 10 in the cloud app) whose names are user-definable per label set, enabling workflow-stage tagging that round-trips through XMP. | xmp:Label field for interop |
| **Hierarchical keywording** | must | medium | Keyword tags organized in a parent/child tree with synonyms, per-keyword export inclusion/exclusion, containing-keyword export, keyword sets, and recently-used suggestion lists. Auto-complete while typing and comma-separated batch entry. | Closure-table or materialized-path tree in SQLite, dc:subject + lr:hierarchicalSubject XMP fields, controlled-vocabulary import (Lightroom keyword-list .txt format) |
| **Painter (spray) tool** | could | low | A click-drag applicator that sprays a chosen payload — keyword, rating, flag, label, rotation, or preset — onto grid thumbnails for very fast bulk tagging. | — |
| **EXIF/IPTC metadata viewing and editing** | must | medium | Full metadata inspector with switchable field layouts; editable IPTC fields (title, caption, creator, copyright, location), read-only EXIF display, metadata presets, and 'sync metadata' to copy fields across a selection. | exiv2 / ExifTool / libexif, IPTC Core & Extension schemas |
| **XMP sidecar round-tripping** | must | medium | Optionally write ratings, labels, keywords, and develop settings to .xmp sidecars (or embedded XMP for DNG/JPEG) and read them back, giving crash-safe redundancy and interoperability with other tools. | Adobe XMP Toolkit SDK (BSD), exempi, exiv2 XMP support |
| **Capture-time editing** | should | low | Shift or set capture timestamps across a selection (e.g. fixing a camera clock set to the wrong timezone), with the option to write the correction back to the files. | exiv2 / ExifTool |
| **Library filter bar (text / attribute / metadata)** | must | high | Three stackable filter rows: free-text search across any or specific fields; attribute filters (flag, rating threshold, label, copy status, file kind); and a drill-down column browser faceting by date, camera, lens, ISO, keyword, etc. Filters can be saved as presets and locked to persist across sources. | SQLite FTS5 or Tantivy (full-text), faceted-count SQL aggregation |
| **Grid view with badges and sorting** | must | medium | Virtualized thumbnail grid with adjustable cell size, overlay badges (keywords, crop, edit, collection membership, GPS), rotation buttons, and sort by capture time, edit time, rating, filename, or custom order. | GPU-accelerated UI toolkits (Qt/QML, Flutter, egui, SwiftUI), libvips for fast thumbnail generation |
| **Loupe view with zoom and info overlay** | must | medium | Single-image view with fit/fill/100%/pixel-zoom levels, click-to-zoom, pan, and a cycling info overlay showing filename, capture settings, and dimensions. | OpenGL/Metal/wgpu textured quad rendering, tiled pyramid rendering for large rasters |
| **Compare view** | should | medium | Side-by-side 'select vs. candidate' comparison with linked zoom/pan and swap/promote controls for choosing the best of near-identical frames. | — |
| **Survey view** | should | low | Displays an arbitrary multi-photo selection together and lets you knock photos out one by one until the keeper remains — the classic wedding-culling narrowing workflow. | — |
| **Filmstrip and secondary display** | should | medium | A persistent thumbnail strip along the bottom for navigating the current source from any view, plus a second-monitor window that can independently show grid or loupe. | — |
| **Multi-tier preview cache** | must | high | Per-photo preview pyramid — embedded/minimal, standard-size (screen resolution), and 1:1 — rendered on demand or at import, stored in a sidecar cache with configurable auto-discard of 1:1 previews after N days. | libvips (fast pyramid generation), LibRaw embedded-JPEG extraction, LRU disk cache patterns |
| **Smart previews (offline editing proxies)** | should | high | Compact lossy-DNG proxies (~2560px) generated on demand so photos on disconnected drives remain browsable, filterable, and even editable, with edits reconciled when the originals reconnect. | Adobe DNG SDK (lossy DNG), alternatively high-quality JPEG/JXL proxies, libjxl |
| **Missing file and folder relinking** | must | medium | Photos whose originals moved or unmounted get an exclamation badge but keep all metadata and previews; a locate dialog relinks one file and auto-finds siblings, and whole folder trees can be re-pointed at a new root. A 'find all missing photos' scan lists every broken link. | Content hashes + filename/size heuristics for match confidence |
| **Stacking** | should | medium | Group related frames (bursts, bracket sets, original+edit pairs) into a collapsible stack showing one cover thumbnail; supports auto-stack by capture-time gap, expand/collapse all, and promote-to-top. | Capture-time clustering (simple gap threshold) |
| **Virtual copies** | must | medium | Zero-cost duplicate catalog entries of one original so a single raw can carry multiple independent edit interpretations (e.g. color and B&W), distinguishable by a page-curl badge and copy name. | Falls out naturally from a nondestructive parametric-edit data model (one image row, many version rows) |
| **Quick Develop panel** | could | medium | Coarse relative adjustments (exposure, contrast, white balance, crop ratio, preset application) applied from the Library without opening the editor; because steps are relative they batch sensibly across differently-exposed selections. | Delta-application layer over the edit-parameter store |
| **People view (face detection and recognition)** | could | very-high | On-device face detection clusters similar faces, users name a few, and the system proposes matches for the rest (confirm/reject loop); named people become searchable keywords and a dedicated browse view. | InsightFace (RetinaFace + ArcFace embeddings), dlib / face_recognition, MediaPipe Face Detection, ONNX Runtime for local inference, hdbscan/faiss for embedding clustering |
| **AI assisted culling** | wont | very-high | Scores every frame for subject sharpness, per-face eye focus, and eyes-open, with user-tunable strictness thresholds that pre-flag keepers vs. rejects; runs on collections or directly at import (added to Classic in 2025-2026). | MediaPipe Face Mesh (eye aspect ratio for eyes-open), Laplacian-variance / learned sharpness estimators, NIMA-style aesthetic scoring models, ONNX Runtime |
| **Duplicate detection view** | should | medium | A background scan indexes the catalog and surfaces content-identical or near-identical images as auto-generated review stacks, matching on pixel content rather than filename or metadata (Classic 15.4, June 2026). | pHash / OpenCV img_hash / imagehash (perceptual hashing), exact-dupe SHA hashing, BK-trees or faiss for near-match lookup |
| **Semantic content search (cloud Lightroom)** | could | high | The cloud product's Sensei search finds photos by describing their content ('dog on a beach') with no manual keywords, via server-side auto-tagging; an open clone can do this fully locally with image-text embedding models. | OpenCLIP / SigLIP embeddings, sqlite-vec / faiss / usearch vector index, RAM++/WD-tagger style open auto-taggers |
| **Multiple catalogs and catalog merge** | could | high | Create and switch between separate catalogs, export any selection as a portable catalog (optionally bundling originals and previews), and import/merge another catalog with conflict resolution — the classic laptop-to-studio workflow. | SQLite ATTACH-based merge, content-addressed IDs to survive renumbering |
| **Catalog backup, integrity check, and optimization** | must | low | Scheduled exit-time backups of the catalog with corruption testing and database optimization (vacuum), keeping timestamped compressed snapshots. | SQLite online backup API, PRAGMA integrity_check, VACUUM, zstd compression |
| **Video asset management** | should | high | Videos import alongside stills with scrubbing thumbnails, playback, poster-frame selection, rough trim, and inclusion in ratings/keywords/collections/filters like any photo. | FFmpeg / libav (thumbnails, playback, trim), GStreamer |
| **Batch rename with templates** | should | low | Rename any selection (or files at import) with token templates combining custom text, sequence numbers, dates, and metadata fields; templates are saved as reusable presets. | Token/template engine over exiv2 metadata |
| **Removal semantics (remove vs. delete)** | must | low | Distinguishes removing a photo from the catalog (file stays on disk) from deleting it to the system trash, with a separate one-command purge of all rejected photos. | OS trash APIs (trash-rs, send2trash) |
| **GPS / location metadata** | could | medium | View and edit GPS coordinates and IPTC location fields, filter by location, and (in Classic's Map module) drag photos onto a map or auto-tag from a GPX tracklog. | exiv2 GPS tags, gpxpy / GPX parsers, offline reverse-geocoding datasets (GeoNames), MapLibre GL (if a map UI is added) |
| **Cloud sync of collections and keywords** | wont | very-high | Classic can sync designated collections (as smart previews) to Adobe's cloud for mobile/web access, with keywords now syncing bidirectionally as of mid-2026; inherently a service feature, out of scope for a v1 local desktop clone. | CRDT libraries (automerge, yjs) if peer sync is ever attempted, self-hosted object storage (MinIO) |
